# 臺北市福利補助自己查｜微服務設計書

版本 0.1｜2026-11-07｜臺北秋季程式設計節「城市通微服務大黑客松」，題目卡「拿不到」

## 1. 概述

本微服務嵌入台北通，讓市民以問答或一句話描述自身狀況，查出可申請的臺北市福利補助，並取得要帶的文件、申辦管道與代辦協助。

- 參照對象：新北市「福利補助自己查」（2013 年起建置，以類別問答比對補助資格）。
- 改良重點：白話結果與符合依據、「還需要確認」的條件、帶去臨櫃清單、請人幫我（代辦協助）、高齡友善介面。

## 2. 目標使用者

| 角色 | 特性 | 主要需求 |
|---|---|---|
| 本人 | 獨居長者、經濟弱勢、偏鄉居民、新住民家庭 | 少輸入、大字、可朗讀、知道下一步 |
| 代辦者 | 子女、照顧者、里長、社工 | 快速查出資格、產生摘要與文件清單 |

## 3. 功能範圍

| 編號 | 功能 | 說明 | 本次 |
|---|---|---|---|
| F1 | 類別入口 | 9 類：生活困難、工作、銀髮、醫療照護、育兒、社會教育、居住交通、教育扶助、上網與設備 | 做 |
| F2 | 一句話查詢 | 文字或語音輸入，轉成類別與條件 | 做（關鍵字規則） |
| F3 | 問答 | 一頁一題，每題可跳過 | 做 |
| F4 | 資格比對 | 符合、可能符合（有未知條件）、不符合 | 做 |
| F5 | 結果與詳情 | 白話說明、金額、符合原因、還需要確認、要帶文件、申辦方式 | 做 |
| F6 | 一覽表 | 依類別列出全部項目，可搜尋 | 做 |
| F7 | 帶去臨櫃 | 合併所選項目的文件清單，大字、可列印 | 做 |
| F8 | 請人幫我 | 選擇家人／里長／社工／1999，產生狀況摘要並分享或撥號 | 做 |
| F9 | 無障礙 | 三段字級、高對比、朗讀、觸控目標 ≥ 48px | 做 |
| F10 | 台北通身分帶入 | 以台北通登入資料預填年齡與設籍 | 不做（以模擬表示） |
| F11 | 線上送件 | 直接送出申請 | 不做（導向既有申辦管道） |

## 4. 系統架構

```
台北通 App（WebView）
   └─ 微服務前端（Expo Router，輸出為靜態網頁）
        ├─ 規則引擎 match.ts（前端執行）
        ├─ 補助資料 welfare-items.ts、問題 questions.ts（隨版本發布）
        └─ 選用：福利 API（見第 7 節）
```

- 前端：Expo SDK 58、expo-router、react-native-web，輸出靜態網頁，可直接嵌入台北通 WebView；同一套程式可編譯為 App。
- 資料：補助項目以結構化檔案隨版本發布，每筆附官方來源網址與查核日期。
- 運算：資格比對在裝置上完成，個人狀況不送出裝置。

## 5. 資料模型

定義於 `app/src/data/welfare-schema.ts`。

| 型別 | 主要欄位 |
|---|---|
| `Profile` | 出生年、設籍月數、福利身分、是否獨居、子女年齡、就業、就學、租屋 |
| `Eligibility` | 年齡區間、設籍月數下限、身分（任一）、獨居、子女年齡上限、就業、就學、租屋、無法以欄位判斷的條件 `notes` |
| `WelfareItem` | 名稱、白話說明、類別、主辦機關、金額、資格、要帶文件、申辦方式（線上／臨櫃／電話）、來源網址、查核日期 |

## 6. 資格比對規則

- 每個條件結果為：符合、不符合、未知（使用者跳過或未問到）。
- 任一條件不符合 → 不符合。
- 全部符合且無 `notes` → 符合。
- 其餘 → 可能符合，顯示未知條件與 `notes` 為「還需要確認」。
- 排序：符合在前；同組依已知條件數多寡排序。

## 7. API 設計（選用，供台北通後端或其他服務串接）

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/v1/welfare/items?category=` | 補助項目清單 |
| GET | `/v1/welfare/items/{id}` | 單一項目 |
| GET | `/v1/welfare/questions?category=` | 該類別問題 |
| POST | `/v1/welfare/match` | 輸入 `Profile`，回傳符合與可能符合項目及原因 |
| POST | `/v1/welfare/help-requests` | 建立代辦協助請求（對象、項目、聯絡方式、同意紀錄） |

- 回應格式為 JSON；錯誤格式 `{ code, message }`。
- `match` 不保存輸入；`help-requests` 僅保存當事人同意分享的欄位。

## 8. 頁面流程

```
首頁 ─┬─ 類別 → 問答 → 結果 → 詳情
      ├─ 一句話查詢 → 結果
      ├─ 一覽表 → 詳情
      └─ 請人幫我
結果 → 帶去臨櫃清單／請人幫我
```

## 9. 無障礙與易用性

- 字級三段（標準／大／特大），設定保留於裝置。
- 對比符合 WCAG AA；朗讀使用瀏覽器語音合成。
- 一頁一題、每題可跳過、可返回；不要求輸入身分證號等敏感資料。
- 375px 寬度無橫向捲動；觸控目標 ≥ 48px；元件具無障礙角色與名稱。

## 10. 隱私與安全

- 問答內容只存在裝置記憶體；重新整理即清除。
- 分享摘要由使用者確認後才送出，摘要不含身分證號與地址門牌。
- 不使用台北市政府標誌，頁尾註明「本服務為黑客松原型，資料以各機關公告為準」。

## 11. 資料維護

- 每筆補助附官方來源與查核日期；查核超過 6 個月的項目在一覽表標示。
- 正式導入時，建議由社會局提供結構化資料或開放資料介接，取代人工整理。

## 12. 測試與驗收

| 項目 | 方法 |
|---|---|
| 規則引擎 | 單元測試：年齡、設籍、身分、未知條件 |
| 型別與程式品質 | `tsc --noEmit`、lint |
| 介面 | 375 與 1280 寬度截圖；首頁、問答、結果、詳情、一覽表、帶去臨櫃、請人幫我 |
| Demo | 3 分鐘腳本完整走過一次 |

## 13. 時程（比賽當日）

| 時段 | 工作 |
|---|---|
| 第 1 階段 | 資料蒐集（30～45 項）、首頁與問答骨架 |
| 第 2 階段 | 規則引擎、結果與詳情、一覽表 |
| 第 3 階段 | 帶去臨櫃、請人幫我、無障礙 |
| 第 4 階段 | 截圖驗收、簡報、Demo 演練 |

## 14. 風險

| 風險 | 對策 |
|---|---|
| 補助條件整理錯誤 | 只收錄可對到官方來源的項目，無法驗證的條件列為「還需要確認」 |
| 與既有查詢網站重疊 | 主打結果可行動：符合原因、帶去臨櫃、請人幫我 |
| 長輩仍不會操作 | 代辦者可代為操作；任何畫面可一鍵請人幫忙或撥打 1999 |

# 福利通：產品規劃與評估紀錄

日期：2026-11-07。狀態：研究規劃，尚非實作或驗收成果。

## 本輪確認紀錄

使用者同意將目前討論的設計全部保留為後續規劃依據；此確認是記錄設計，不代表已授權實作、部署或對外合作。

- 聚焦福利取得障礙；題目列出的設備補助與公共網路不視為必做功能。
- 保留簡單首頁、資格初篩、協助者模式、PDF／文字行動單、真人協助出口及選配端側 AI。
- 加入辦理路線：步驟卡、必要文件、正確機關、官方網站、電話與地址，提供目前步驟及完整流程。
- 第一版優先完成「步驟卡＋官方網站＋電話＋地址＋可列印路線」；導航為次要入口，方案須符合競賽規範，不另建複雜交通系統。
- 獨居長者依操作能力、能否到場及有無協助者分流，不預設必須有家人；完全沒有設備也沒有接觸協助者的人，單靠 App 無法主動觸及，實際接觸仍需服務據點或合作。
- 偏鄉情境沿用辦理路線，重點是確認管轄、減少白跑與呈現已確認的遠端方式；地方資料不足時明示範圍。
- 以上皆為待資料查核與實作驗證的設計，不因新增構想而宣稱提高實際成效或評分。

## 定位與範圍

題目為「03｜拿不到－資源限制」，對象包含經濟弱勢、偏鄉居民、獨居長者；方向包含數位設備補助、公共網路、保留實體服務管道。

依後續討論，題目圖的「方向」視為建議切入點，不視為三項必做要求；如有其他正式條文再核對。產品聚焦福利取得障礙，不因缺少設備補助或公共 Wi-Fi 功能而扣主題分。

定位：「福利通｜把資源變成下一步」。從生活需求出發，提供可解釋初篩、文件與窗口指引，最後交付可攜帶的資源行動單。不能將產生摘要等同送件、核准或取得福利。

使用者表示已蒐集中央及臺北市大量補助、福利、獎學金與獎金資料，但尚未整理；覆蓋率、品質、授權與時效尚未逐筆驗證。

## 介面與流程

- 首頁三入口：找適合我的資源；繼續準備申請；找人協助。設備補助可作為一般資源，不設獨立首頁入口，不將公共 Wi-Fi 地圖列入核心範圍。
- 提供本人與替他人查詢情境，不將登入者資料自動套用到受助者。
- 流程：選需求 → 少量相關問題 → 候選資源與原因 → 文件／窗口／待確認事項 → 行動單 → 真人協助入口。
- 每題容許不知道或暫不提供；區分居住地與戶籍、生活困難與法定資格。
- 障礙排除入口：「這一步有哪裡做不到？」依已查核資料提供文件取得、電話諮詢、委託或非線上途徑。沒有來源不得推定可代辦或到宅服務。
- 介面遵循 TownPass 規範，簡單導航、清楚文字、大按鈕，測試文字放大與螢幕閱讀器。

## 辦理路線：長者與跨地區使用者的引導

新增設計：以直式步驟卡呈現辦理流程，重點是先後順序、正確受理單位與可替代方式，不自行開發複雜交通導航。先顯示「現在先做這一步」，完整流程可展開及列印。

使用者可選自行辦理或需要協助，並表示能否到場、能否使用線上服務；不從年齡推定操作能力。沒有家人協助者仍須可直接取得有來源的電話／實體協助入口。

每一步包含：要做的事、必要或條件式步驟、前置條件、所需文件、預期取得結果、承辦單位與管轄、電話、地址、官方網站、服務時間／預約要求、來源與查核日期。資料缺漏明示待確認，不能由 AI 補造。

示意流程（不是任何特定補助的正式流程）：確認適用地區與受理方式 → 準備必要文件 → 線上或實體辦理 → 保存收件證明／依官方方式追蹤。資料足夠時省略不必要步驟，不要求每個人先打電話或額外跑機關。

- 每張卡提供「撥電話」「開官方網站」「查看位置／前往方式」及「這一步做不到」。
- 導引到真正有受理權限的單位，不單按距離選最近機關。分清主管機關、文件核發單位、受理窗口與諮詢單位。
- 手動選縣市及行政區即可，定位選用；區分戶籍地與居住地，依個別資源規則決定管轄。
- 線上、郵寄、委託、到宅等方式只在來源確認後呈現；不能把諮詢入口說成已安排協助或正式轉介。
- 導航為次要入口，先提供地址與位置。地圖及外部導航方案依競賽開源規定核對後選用，不預設可用特定商用服務；第一版不做即時路線規劃。
- 沒有人陪同且不能出門時，提供已查核的協助電話及照讀詢問文字；若沒有替代方式，明示目前無法完成該步並提供適當諮詢出口，不假裝已有接案服務。
- 個人勾選狀態僅代表準備進度，不代表官方受理或核准。無網路可查看已儲存路線；外部網站與即時交通仍需網路。
- 偏鄉使用者同樣受益於減少白跑與遠端辦理指引，但未具備該地資料時不得推論地方福利或服務涵蓋完整。

驗收情境：不懂操作但能到場的長者、沒有家人且不能到場者、戶籍與居住不同縣市者、缺少文件者。檢查是否能找到正確第一步、遇到障礙是否有真實出口，以及紙本能否獨立使用。上述為設計，尚無實測成果。

## 市民交付

優先提供 A4 PDF 與純文字摘要，圖片小卡為次要。內容包含需求、選定資源、已確認與待確認事項、文件清單、窗口、建議詢問內容、官方來源及資料版本。

標示「申辦準備摘要，非核准或送件證明」。預設排除姓名、身分證、精確收入、病史與住址；分享前預覽。QR Code 第一版只連公開資源頁，不嵌入個人摘要。官方表單與自行生成的摘要分開。

須實機驗證 WebView 存檔、分享、取消與失敗備援。

## AI 與離線

Gemma 4 E2B 為選配需求理解與白話解說助手；需求抽取須經使用者確認。資格、日期、金額及文件由資料與規則提供。

先建立原版模型加檢索的基準，再評估教師模型產生並經審核的訓練範例與 LoRA。微調須證明優於基準，並驗證匯出、量化及實機表現；不得把變動政策主要儲存在權重中。

輕量無 AI 流程應可獨立完成。離線功能須包含網頁外殼、資料與規則，斷網重新開啟驗證；模型可離線不等於整個服務可離線。

## 資料需求

每筆需有名稱、主管機關、資源類型、適用地區、對象、受理期間、資格與排除條件、文件、申辦方式、窗口、來源段落、授權、版本與查核日期。

區分資格型補助、名額審查型獎學金及競賽型獎金。未整理資料保留內部；已整理資料可搜尋；已查核資料才提供完整規則初篩。未知條件不得等同不符合。

## 優先順序

1. 先完成 5–8 項已查核資源的完整流程、協助者情境、行動單與失敗處理。
2. 擴充至 20–30 項，加入原版 E2B 需求整理與一組離線資料。
3. 後續評估微調、跨裝置接續、文件辨識及更新提醒。
4. 正式送件、案件進度與承辦人接案須有官方介面或合作，不列為目前已具備能力。

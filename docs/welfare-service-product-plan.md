依後續討論，題目圖的「方向」視為建議切入點，不視為三項必做要求；如有其他正式條文再核對。產品聚焦福利取得障礙，不因缺少設備補助或公共 Wi-Fi 功能而扣主題分。

定位：「福利通｜把資源變成下一步」。從生活需求出發，提供可解釋初篩、文件與窗口指引，最後交付可攜帶的資源行動單。不能將產生摘要等同送件、核准或取得福利。

## 介面與流程

- 首頁三入口：找適合我的資源；繼續準備申請；找人協助。設備補助可作為一般資源，不設獨立首頁入口，不將公共 Wi-Fi 地圖列入核心範圍。
- 提供本人與替他人查詢情境，不將登入者資料自動套用到受助者。
- 流程：選需求 → 少量相關問題 → 候選資源與原因 → 文件／窗口／待確認事項 → 行動單 → 真人協助入口。
- 每題容許不知道或暫不提供；區分居住地與戶籍、生活困難與法定資格。
- 障礙排除入口：「這一步有哪裡做不到？」依已查核資料提供文件取得、電話諮詢、委託或非線上途徑。沒有來源不得推定可代辦或到宅服務。
- 介面遵循 TownPass 規範，簡單導航、清楚文字、大按鈕，測試文字放大與螢幕閱讀器。

## 辦理路線：長者與跨地區使用者的引導

新增設計：以直式步驟卡呈現辦理流程，重點是先後順序、正確受理單位與可替代方式，不自行開發複雜交通導航。先顯示「現在先做這一步」，完整流程可展開及列印。

使用者可選自行辦理或需要協助，並表示能否到場、能否使用線上服務；不從年齡推定操作能力。沒有家人協助者仍須可直接取得有來源的電話／實體協助入口。

每一步包含：要做的事、必要或條件式步驟、前置條件、所需文件、預期取得結果、承辦單位與管轄、電話、地址、官方網站、服務時間／預約要求、來源與查核日期。資料缺漏明示待確認，不能由 AI 補造。

示意流程（不是任何特定補助的正式流程）：確認適用地區與受理方式 → 準備必要文件 → 線上或實體辦理 → 保存收件證明／依官方方式追蹤。資料足夠時省略不必要步驟，不要求每個人先打電話或額外跑機關。

- 每張卡提供「撥電話」「開官方網站」「查看位置／前往方式」及「這一步做不到」。
- 導引到真正有受理權限的單位，不單按距離選最近機關。分清主管機關、文件核發單位、受理窗口與諮詢單位。
- 手動選縣市及行政區即可，定位選用；區分戶籍地與居住地，依個別資源規則決定管轄。
- 線上、郵寄、委託、到宅等方式只在來源確認後呈現；不能把諮詢入口說成已安排協助或正式轉介。
- 導航為次要入口，先提供地址與位置。地圖及外部導航方案依競賽開源規定核對後選用，不預設可用特定商用服務；第一版不做即時路線規劃。
- 沒有人陪同且不能出門時，提供已查核的協助電話及照讀詢問文字；若沒有替代方式，明示目前無法完成該步並提供適當諮詢出口，不假裝已有接案服務。
- 個人勾選狀態僅代表準備進度，不代表官方受理或核准。無網路可查看已儲存路線；外部網站與即時交通仍需網路。
- 偏鄉使用者同樣受益於減少白跑與遠端辦理指引，但未具備該地資料時不得推論地方福利或服務涵蓋完整。

驗收情境：不懂操作但能到場的長者、沒有家人且不能到場者、戶籍與居住不同縣市者、缺少文件者。檢查是否能找到正確第一步、遇到障礙是否有真實出口，以及紙本能否獨立使用。上述為設計，尚無實測成果。

介面以「這次要幫誰找資源？」搭配「自己／家人或其他人」選項呈現，不強調模式名稱。兩者共用搜尋、資格初篩、辦理路線及行動單，只改變資料所屬對象與問句。

### C. 資格與排序

內部條件採符合／不符合／未知三態；資格結論與資料完整度分開計算。

- `allOf`：任一確定不符合則該群組不符合；全部符合才符合；否則未知。
- `anyOf`：任一群組符合即符合；全部不符合才不符合；其餘未知。
- 需人工查核的關鍵條件、缺失規則、過期版本均使結果保留待確認。區分關鍵條件與一般說明，不把每段備註都當成資格條件。
- 對使用者顯示「已知條件相符，仍須機關審核」「還有條件待確認」「目前條件不符」，不給核准機率。
- 年齡門檻附近僅有出生年時不得確定判斷，需確認生日或保留未知；優先避免蒐集完整生日。
- 明確必備條件不符時，即使其餘條件未知仍應排除；不能將所有未知都當成保留不適合資源的理由。原始資料缺少條件關係時，以來源綁定的審閱規則補足；多途徑、子女／配偶、年度基準等未確認部分維持未知，不猜測。
- 明確區分尚未回答、回答否、略過與不知道；生活困難不是低收入戶證明。
- 排序先按需求與適用地區、資料可用性及條件狀態；截止日期作次要提醒。不要使用符合條件數作核准機率，也不因規則寫得少而優先推薦。
- 沒結果顯示目前資料覆蓋、修改條件與詢問窗口，不宣稱沒有任何福利。
- 獎學金另顯示名額／審查，競賽獎金另顯示評選；資格相符不等於獲選。

### D. 辦理路線與文件合併

每項資源以有來源的步驟與前置依賴描述，支援線上／臨櫃等已確認的替代分支；第一版以人工查核的直式流程呈現，不讓 AI 自行編排行政程序。

先選適用管轄與承辦能力，再依需要提供位置。距離只用於合格窗口間的參考；行政區中心的距離須標示估計，不能當成使用者位置或交通時間。

文件採文件 ID、版本／適用期間、正影本要求、份數、取得方式與各資源用途。只合併確認等價的準備事項，保留各項不同要求；有相同名稱而條件不同者分列。文件清單空白須標示尚未補齊，不視為免附文件。

「這一步做不到」至少提供：不知道如何取得文件、不方便到場、沒有協助者、無法線上操作、看不懂要求。每個選項導向有來源的替代方式，或具體詢問問題；沒有已知替代方式時如實顯示。

### E. 保存、輸出與隱私

- 字級與高對比可保存於裝置；答案預設只保存於本次工作階段，允許重新整理後繼續，但不宣稱所有 WebView 關閉後一定清除。
- 「下次繼續」需使用者主動選擇本機保存，標示保留期限、提供立即清除；第一版不做跨裝置帳號同步。共用設備預設不長期保存個人答案。
- 第一版保留重新整理後的文件勾選及步驟準備狀態；狀態限未開始／準備中／使用者標記已準備，不標示官方受理或核准。
- 行動單保存資料版本；資料更新後重新判斷受影響條件、文件與步驟，不默默沿用舊結論。
- 分享先選對象、預覽並可移除敏感欄位；同意適用本次內容與對象，變更後重新確認。複製失敗提供可選取文字；分享取消與真正錯誤分開處理。
- PDF、純文字與畫面來自同一份行動單內容；PDF 優先支援可選取文字、清楚列印與來源。若實機只能列印，明示尚未完成檔案匯出，不冒稱 PDF 已完成。
- QR Code 僅指向公開資源；個人檔案不自動上傳。輸出前說明檔案分享後由接收者持有。

### F. 前後端與 AI 分工

建議模組責任：ResourceRepository 讀取版本化資料；EligibilityEvaluator 執行規則；SituationInterpreter 理解需求；JourneyBuilder 組合已查核步驟；ActionPlanExporter 輸出行動單；TownPass adapter 封裝原生能力。名稱是設計建議，實作時依現有結構調整。

後端尚未完成時，先用統一結構的已查核 JSON；未來 API 透過相同讀取介面接入，頁面不綁定後端。後端負責資料整理、查核發布與更新；第一版資格比對在裝置端，無須上傳個人答案。

資料實體至少包含 Resource（類型、範圍、期間）、Eligibility（條件群組及證據）、DocumentRequirement（文件要求）、ServicePoint（受理能力及管轄）、ApplicationStep（依賴與替代方式）、SourceRecord（來源、授權、版本及查核）、ActionPlan（選定資源與準備進度）。正式欄位定案須先檢查實際資料樣本。

需求理解介面固定回傳需求標籤、候選欄位、未確定事項與支持的輸入片段。規則及 Gemma 共用此介面；輸出通過格式／允許欄位檢查並由使用者確認。測試否定、兩個人物、矛盾敘述與無法理解情況。模型不負責核准、填造金額／日期／機關，解說只能使用取回資料。

核心流程不依賴 AI。模型下載需可略過，記憶體不足、超時與取消回到按鈕問答。微調在原版＋檢索基準建立後再做，保留獨立測試資料，避免訓練與評測重複。

### G. 實作順序與驗收門檻

必要檢查：純規則測試（allOf／anyOf／未知／年齡界線／人工條件）；資料欄位與來源關聯；Vue 型別及建置；TownPass 實機的預填、撥號、開站、檔案；放大字體與鍵盤／讀屏；離線重開與過期資料。測量任務完成率、第一步理解正確率、錯誤資格判定及匯出成功率，先建立基準，不預設已改善。

### H. 三個端到端示例

以下皆為合成情境，資源 A／B／C 為占位名稱，不代表真實福利資格或辦理規定。

1. **72 歲獨居長者**：選生活支持 → 不知道福利身分 → 系統顯示 A 尚待確認家庭條件 → 查看來源支持的辦理步驟 → 點「不能自己到場」 → 顯示適當窗口與照讀詢問文字 → 儲存大字行動單。若志工代查，使用協助者模式；沒有設備且沒有人接觸時，App 本身仍無法主動觸及。
2. **戶籍外縣市、在臺北就學的學生**：選就學費用 → 分開回答戶籍與就學地 → 中央 B 與有來源支持的學校／地方項目分別列示 → 不符合的臺北設籍要求可解釋 → 選兩項後合併等價文件、保留各自期限及份數 → 依官方網站送件。未取得政府回覆前只記錄準備狀態，不顯示已核准。
3. **交通不便地區的居民**：手動選居住及戶籍地 → 找到適用的中央 C → 先看有無已確認的遠端方式 → 有則連官方入口，沒有則提供正確受理窗口的詢問方式 → 列印文件與路線減少白跑。沒有該地資料時說明涵蓋限制，不填入最近但無權受理的機關。

### I. 競賽呈現與接手

初選兩分鐘以第一情境為主：需求 15 秒、問答與待確認結果 35 秒、辦理路線及障礙出口 40 秒、行動單 20 秒、來源與技術邊界 10 秒。決選五分鐘再展示協助者或跨地區情境及離線／失敗備援；只展示已實作功能，模擬角色清楚標示。

交付包含原始碼、可重現建置說明、資料來源及授權、第三方清單、已知限制、測試證據；有 AI 才附模型版本、格式、推論框架與取得方式。市民 PDF 與競賽原始碼交付分開，不用前者代替後者。

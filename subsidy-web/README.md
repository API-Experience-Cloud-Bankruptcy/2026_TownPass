# 福利連｜補助專區微服務

城市通「服務 › 熱門 › 補助專區」開啟的網頁。Vue 3 + Vite + TypeScript，建置為靜態檔，在城市通 WebView 中執行。

逐頁選擇查詢對象 → 選「還不確定，帶我找」、生活情境或名稱搜尋 → 一頁一題的動態問答 → 建議先看的幾項＋可展開的其他候選 → 詳情與辦理路線 → 準備文件／預覽並輸出行動單。「補助總覽」先顯示分類卡片，選類別後列出該類所有項目，也可直接跨類別搜尋。**本服務非政府官方服務**；產生的內容是申辦準備摘要，**不是核准或送件證明**。

## 介面原則

- 每頁只處理一個決定；本人與替他人共用流程，問句依查詢對象調整，不推測資格。
- 需求頁有三條入口：醒目的「還不確定，帶我找」（`startExplore`）、生活情境分類、名稱或關鍵字搜尋；切換時清掉另一條的篩選。
- 問答不顯示固定總題數：題目由 store 依前面答案重新決定，畫面只說「已回答 N 題・目前聚焦 N 項」。「目前聚焦」是依填答去掉明確不符、再依探索方向收斂後的筆數，不是符合資格的數量；偏好收斂不說成資格排除。每題直接顯示這題的用處（`description`），可「不知道，先跳過」（不當成「否」）、「上一題」改答案、「先看目前結果」。回答後以一行文字如實回饋聚焦數是否變少（比較作答前後的 `questionInsight.remainingCount`），不預測下一題會縮小多少；題目問完時說明「目前仍有條件需要確認」。
- 結果頁先列「先從這幾項了解」（`recommendedCandidates`），其餘收在可展開區：「其他相關資源」、「受理時間需確認」（`uncertainCandidates`）；明確與填寫條件不符的項目不列在結果頁。分組依 store，畫面不自行判斷截止或資格；同一項只出現在一組（建議 → 受理時間需確認 → 其他）；已截止案件在 `candidates` 就排除，不會出現在結果，各組數量為實際列出筆數。「再回答幾題，繼續縮小」呼叫 `continueQuestions()`（接續本次，延長題數）；「改答案」呼叫 `startQuestions()`（從頭檢視、保留答案）。全部略過時仍可看資料，但標明不是依個人情況挑選。
- 清單列與詳情都標示填寫條件不符、期限可能已過、受理情形原文提到截止或未開放。
- 詳情依序為「先看重點」（白話導讀）→「能提供什麼」（補助內容原文全文）→「要先注意」（提醒、適用對象原文、受理情形、期限）→「想申請的話」（加入行動單、申請方法連結）→ 辦理步驟、文件、窗口；完整初篩說明及來源可展開。
- 「行動單」固定管理本人項目，分成概覽、文件準備與匯出；補助總覽詳情只提供加入行動單。找資源選「幫家人或別人找」時，詳情改為「匯出申請準備 PDF」，預覽目前單筆資源後下載或分享，不加入本人行動單。
- 簡化的是畫面資訊量；原始條件、來源及完整匯出內容保留。返回修改不清除同一人的答案，換人仍需確認。
- 白底、留白與細分隔取代彩色提示框及深色側邊線。短句先說明下一步，官文按需展開；不以簡化文案取代正式資格。

頂部品牌列與分頁固定於畫面上方；「找資源」輸入框固定於底部，只有中間對話區捲動。離開進行中的「找資源」後返回，提供「開新對話／繼續對話」；仍停在初始招呼頁時不彈框，繼續時保留原題目與本次對話紀錄。

## 補助總覽

- 從總覽進入詳情一律使用本人行動單與本人條件，不沿用替他人查詢的答案，也不顯示他人 PDF 匯出入口。
- 原「找人幫忙」主要分頁改為「補助總覽」；不須先回答問題。預設顯示「查看全部」與 11 類卡片及筆數，可列出整份收錄資料或該類全部項目；詳情返回保留類別、關鍵字及篩選。
- 直接輸入關鍵字可跨分類搜尋，選類別後則搜尋該類。沿用本站 `situations.ts` 的加權子字串搜尋：名稱 8、關鍵字 5、分類／對象／機關 3、內文 1；臺台同義，多個詞取交集。現有 217 筆無須新增第三方搜尋套件，無額外服務或授權依賴；不含語意搜尋或錯字推測。
- `browse.ts` 依臺北當日、結構化起訖日期與資料受理狀態標示時效；總覽列出受理時間待確認及尚未開放項目，後者排在最後；已截止案件不列出。頁面每分鐘更新當日日期。
- 筆數只代表目前收錄的資料，不代表全臺所有補助或個人符合資格；原始資料不是即時名額／預算資訊。這項改版未重新查核官方公告，也不修改問答答案、資格規則或行動單；原問答的其他候選查詢保留。
- 期限顯示共用 `domain/deadline.ts`：有日期／時間先顯示日期與必要適用範圍，無日期用短說明；完整原文在詳情與行動單內展開，PDF 摘要同步精簡、內文仍保留完整期限。`content/deadline-summaries.json` 綁定逐筆審閱的期限來源，來源改變即停用舊摘要；公告日、給付期間、校例與不同梯次不能當作統一申請期限。
- 全部 217 筆經逐筆編輯的白話導讀位於 `src/content/plain-language-*.json`，總覽與結果卡標示「白話導讀」，詳情以「誰可以先了解／能得到什麼幫助／第一步怎麼做／申請前先確認」呈現。導讀不代替完整條件，官方原文可從詳情展開。詳情另按年齡、所得、戶籍等分組列出每條資格、排除條件及擴充原文；長原文只在既有句號、分號或換行處分段，不改名稱、數字、政策用語或來源，也不把節錄當作完整資格。

導讀透過 `domain/plain-language.ts` 與 `plain-language-sources.json` 綁定當時的名稱、資格、給付、申辦、擴充和來源內容。API 資料改變或新增項目時，不顯示舊導讀，清單退回明確標示的原文節錄。更新資料時須重新閱讀受影響的項目、修訂導讀與來源指紋，不可只更新指紋讓測試通過；`plain-language.test.ts` 檢查整份資料的 ID 覆蓋與來源一致性。這些是既有資料的文字整理，不代表重新查核政策或受理狀態。

## 開發

需要 Node.js 20 以上。

```bash
cd subsidy-web
npm install
npm run dev        # http://localhost:5173，同時對區域網路開放
npm test           # Vitest 單元測試
npm run build      # vue-tsc 型別檢查並輸出 dist/
```

## 資料來源與 API

| 設定 | 說明 |
|---|---|
| 開發 | `npm run dev` 時 `/api` 由 Vite proxy 轉到 `http://127.0.0.1:8080`（先啟動 `backend/`） |
| 正式 | 建置時設定 `VITE_API_BASE_URL=https://<後端網域>`，網頁會讀 `${VITE_API_BASE_URL}/api/catalog` 與 `/api/questions` |

- `GET /api/catalog` 回傳 `{version, items}` 完整原始資料（217 筆）；前端逐筆驗證實際用到的欄位（scope、search、application、eligibility 陣列等），任何一筆不符、逾時（8 秒）或連不上，就改用**建置快照**。
- 建置快照是 `backend/data/subsidies.json` 原始檔逐字打包（`vite.config.ts` 的 `virtual:catalog-snapshot`，獨立 chunk、按需載入），結構與 API 相同。版本 `catalog-v1-<FNV-1a 64>` 以原始文字計算，與後端一致；資料版本變更時會重新判斷並重設準備進度。
- 使用快照時頁面會明示「暫用已保存的資料，官方網站仍需連線」。這只是 API 備援，**不是完整離線模式**：沒有 Service Worker，網頁本身與外部官方網站仍需網路。
- `GET /api/questions` 不可用時使用本機共用模板題庫（`backend/rules/question-templates.json`），出題依據與後端相同。探索映射與必要資格條件分開；每次回答依剩餘候選重排有用題目與探索選項，並處理略過、返回、改答及分支失效。`startQuestions()` 重新檢視答案，`continueQuestions()` 接續未問的題目。題目不由 AI 生成，不保證回答固定題數即可確認資格。
- 查核標記（verified／partial／unverified）與查核日期都是**資料原有狀態**，本服務未重新查核。各筆的來源網址列於詳情頁，依 `source_meta.sources[].type` 標示官方、第三方或「來源類型未標示」。

## 隱私：答案只在本機

- 答案與對話狀態只存在**本分頁的這次工作階段**（`sessionStorage`，`welfare-tong:session:v1`；本人行動單的本分頁資料另存 `welfare-tong:personal-plan:v1`），資格答案在瀏覽器端評估，不送後端；`POST /api/match` 不會被自動呼叫。本人行動單的資源項目、文件勾選與步驟進度透過 `/api/personal-action-plan` 存後端 SQLite，關閉分頁再開啟可還原。須啟用後端 `DEMO_MODE=1` 並保留同一份 `PLAN_DB_PATH`，設定見[後端說明](../backend/README.md)。保存失敗會明示並可重試，不以本機暫存假裝成功。
- 在對話輸入「重新開始」並確認後，移除分頁答案並同步清空資料庫行動單，同時移除舊版 `localStorage` 的同名資料；實際資料庫結果以保存狀態為準。切換查詢對象或「換人」仍先確認再清除前一位查詢答案；自己的行動單及準備進度獨立保留。「開新對話」也保留行動單。字體大小設定不受影響。
- 啟動時 catalog 與題庫都載入成功後，才一次套用新資料與版本遷移；資格規則、探索映射及題目模板皆納入引擎版本。版本變更時重設受影響的探索答案、已問題紀錄與準備進度；載入失敗則保留原狀態並顯示重試。
- 不讀取城市通 `userinfo` 作為任何人的資格條件。App、瀏覽器與 Demo 資料庫共用「陳福利（虛擬）」測試者；欄位、官方資料來源與正式介接限制見[台北通資料說明](../docs/townpass-profile.md)。目前是共用測試帳號，尚未串接正式登入。
- 輸出（行動單）預設不含填答條件；勾選加入的條件才會出現，含填答值的初篩說明也只在對應條件勾選後輸出。

## 資格初篩規則（保守）

`src/domain/match.ts`，與後端 `matcher.rs` 對齊：

- 結果只有「還有條件待確認」與「目前條件不符」。`likely` 保留在型別中但現階段不發出。
- 兩端共用 `backend/rules/eligibility-reviewed.json` 的來源綁定必要條件。明確必備條件不符時可排除，不會因所得或文件尚待確認而忽略已知不符。每條規則保留證據位置與原文，資料變更即停用舊規則。
- `backend/rules/adaptive-reviewed.json` 保存 217 筆逐筆探索分類、證據與未能自動判斷的原文；探索方向不合只影響聚焦與排序，不改成資格不符。新增學制、失業事實、承租／所有權、身障證明等必要條件只對經審閱的個別方案生效；當期資格與完整例外仍須確認。
- 不把其他家庭成員的年齡套到本人；年度、出生年、生日邊界與替代途徑分開處理。無法確定的主體或例外保留待確認。
- 只有已審閱的必要戶籍、在學、家庭身分可排除；不能由分類、scope 或欄位存在推定必備。所得與財產仍不比較。未回答與明確回答否不同。
- 每筆的 `raw_summary`、所得、財產、身障、就業、國籍、排除條件、擴充原文都列為「還要確認」。

## 辦理路線與交付

- 行動單目前步驟提供「這步完成了」與「這一步做不到」。後者在步驟內展開可能困難與處理建議，不修改完成進度；換方案或完成該步時清除展開內容。`domain/step-help.ts` 以當步原文排序問題，並引用同一方案的流程、文件、窗口與來源；未命中時仍有一般說明及其他問題。建議為固定提示，不代表已確認替代辦理方式，方案層級方式不可直接推定每一步適用。沿用現有按鈕、卡片、展開資料與外部連結樣式，不提供獨立求助分頁。

- 步驟只在 `process_text` 有明確箭頭時拆分，否則整段顯示；窗口、文件、網址都取自原文，不補造電話、地址或窗口。網址只允許 http/https。
- 行動單文件只在名稱、條件、備註、必要性完全相同時合併，並保留用途；同名不同要求分列。勾選只代表自己準備好，不代表送件。
- 已審閱的文件條件修正以來源綁定 overlay 套用至路線、合併清單及匯出；原始 JSON 保留。選附文件的「非必要」標記也保留在文字與列印內容中。
- 本人輸出維持複製文字、下載純文字（.txt）、系統分享與「列印／另存 PDF」。
- 替他人查詢：結果詳情按「匯出申請準備 PDF」，在同頁自動製作目前單筆資源的 A4 PDF，預覽後下載或分享（不依賴列印對話框），不透過行動單。可先標記已備妥文件；PDF 包含共用文件清單、各資源完整資格、保守初篩及待確認事項、受理期限、窗口與步驟、來源及查核紀錄、照讀求助問句與手寫欄。長內容自動分頁，不以一頁限制刪除條件；每項資源另起新頁。
- PDF 由裝置端 `pdf-lib`／`fontkit` 產生，第一次預覽才載入本站的 Noto Sans TC 字型（約 7.1 MB），完整字型嵌入 PDF（約 4.2 MB，避免子集在閱讀器缺字）。無 CDN 或雲端 PDF 服務；尚未提供完整離線快取。檔案可複製文字與點擊來源連結；罕見不支援字元以 Unicode 碼位標示，避免靜默漏字。
- 預設不附個人填答；僅勾選條件才揭露對應填答值。內容、答案、勾選或對象改變時，撤銷舊 PDF，須重新預覽；換人清除前一位查詢答案與他人暫存進度，保留本人行動單。
- 一般瀏覽器使用 PDF 下載、開啟與 Web Share 檔案分享；不支援時保留完整可選取／複製文字。App 以 `share_pdf` 將使用者確認的 PDF 交給系統分享選單，可自行儲存到檔案或交給家人，最高 10 MiB。平台回覆僅表示提出開啟分享，不證明已保存、送出、申辦或取得委託權。舊 App 尚無 handler 時會逾時，需更新 App；手機 WebView 交付仍須實機驗收。

## 裝置端模型

輸入框已合併：先比對目前可見選項，再判斷名稱／關鍵字搜尋或自然情況理解。完整選項、需求簡稱（例如學費、租屋、失業）、受限同義詞與合法數字可直接作答；錯字候選與模型推測先確認，填答中切換搜尋也先確認。詳細分流、限制及正常／異常案例見 [單一輸入規則](../docs/unified-input-policy.md)。

`src/domain/model.ts` 透過 App 的 `llm_status`、`llm_prepare`、`llm_interpret` 連接裝置端原版 **Gemma 4 E2B**。首次進入且尚未下載時，會詢問是否下載約 2.6 GB 的模型；同意後下載並自動載入。之後進入微服務時，已下載模型會自動載入，已就緒則直接使用。取消仍可使用選項與名稱搜尋，下次開啟補助專區會再詢問；載入失敗時對話上方會出現「重試」；一般瀏覽器與舊版 App 不模擬推論，保留畫面選項與明確的名稱搜尋。

- 每個對話階段都可輸入。完整選項文字及目前年齡題的單一合法數字走原本按鈕流程；完整單句本人年齡（例如「我今年 20 歲」）不受目前題目限制，先確認再記下，不由年齡推定學生、需求分類或資格。其他自然語句交裝置端模型理解，模型猜出的當前答案也先確認；只提供已確認條件、當前問題／需求及九類來源綁定分類摘要，不傳整份補助原文。
- 清楚對應目前題目的一個答案沿用 `answerAndAdvance`。單一明確條件或單一方向用「對／修改」接話，也接受在確認中輸入「對」；多人、多條件與多方向仍明選同一位及要採用的內容，不能用一句「對」全部套用。只有條件、還沒有需求時，確認後從全資料的既有生活情境題接續探索，跳過已知基本條件；換方向不重問已確認的年齡。
- 生活困難不推定為低收入戶，居住地不推定為戶籍，不把親人的條件套到本人；不支援或不確定內容保留待確認。題庫、資格與結果仍由原有資料及規則決定。取消、切題、換人與過期回覆均不覆寫新狀態，原始輸入不新增至持久儲存。
- 名稱搜尋零命中時保留原需求、篩選、答案與行動單，改問想解決的困難並提供九類方向／探索入口。模型錯誤、閒聊、模糊或只有敘述時，接一個當前可回答的問題與操作選項；最近澄清原句只在記憶體中保留有限長度，供下一次補充理解。
- 輸出仍採嚴格 schema、選項與欄位白名單、原文證據與請求 ID 檢查。格式驗證不保證模型語意正確。2026-11-08 已補上分流矩陣、條件保留及一般瀏覽器回歸驗證；裝置端模型與手機 WebView 的語意驗收仍須實機操作。

本次操作順序見 [手動試用流程](../docs/chatbot-manual-trial.md)，屬供使用者操作的預期行為；原始設計與異常案例見 [對話輸入說明](../docs/conversation-input.md)。原始模型來源、版本、量化及推論框架見 App 的裝置端模型文件；沒有呼叫雲端 LLM。

## 無障礙

每頁一個標題、換頁焦點移到標題、跳到主要內容連結、按鈕至少 48px、可見焦點框、右上角設定可用拉桿調整字體大小（90%–150%，根字級 14.4–24px）、確認對話框使用原生 `<dialog>`（Esc 可關閉、焦點回到觸發按鈕）、表單錯誤以 `aria-describedby`／`role="alert"` 連結，375px 寬不水平捲動。讀屏與 200% 放大尚待實機驗證。

## 在實機的城市通裡開啟

1. 電腦與手機連同一個網路，啟動後端與 `npm run dev`。
2. 查電腦的區網 IP：`ipconfig getifaddr en0`（macOS）。
3. 在專案根目錄以該網址建置城市通：`flutter run --dart-define=SUBSIDY_URL=http://<電腦 IP>:5173`
4. App 內進入「服務」頁，點熱門的「補助專區」。

正式網址須為 HTTPS。

## 雙向溝通

`src/townpass/` 封裝與 App 的溝通（`window.flutterObject`）。本服務使用 `openLink`（App 內開啟外部網址）與 `call1999`；不使用 `getUserInfo` 作為資格條件。

| 函式 | App 訊息 name | 回覆 |
|---|---|---|
| `getUserInfo()` | `userinfo` | 帳號資料，型別見 `types.ts` |
| `getLocation()` | `location` | 經緯度等定位資料 |
| `getDeviceInfo()` | `deviceinfo` | 裝置資訊 |
| `scanQRCode()` | `qr_code_scan` | 掃到的文字，不逾時 |
| `phoneCall(number)` | `phone_call` | 能否撥號 |
| `launchMap(url)` | `launch_map` | 能否開啟 |
| `call1999()` | `1999agree` | 成功時不回覆 |
| `notify(title, content)` | `notify` | 成功時不回覆 |
| `openLink(url)` | `open_link` | 成功時不回覆 |
| `sharePdf(bytes, filename)` | `share_pdf` | `presented`／`cancelled_or_unavailable`／`failed`；非送達證明 |

## 已知限制

- 未實機驗證：WebView 內的下載、分享、列印／另存 PDF、`openLink`、1999、讀屏與 200% 放大，以及動態問答的換題焦點與回饋朗讀。
- 非完整離線：無 Service Worker；快照只在 API 失敗時作資料備援。
- 資料沒有獨立的電話、地址欄位，路線只顯示窗口原文。
- 快照 chunk 約 1.7 MB（gzip 約 240 KB），首次 API 失敗時才下載。
- 逐筆審閱與探索映射隨主程式載入，目前主程式約 2.64 MB（gzip 約 359 KB），仍有建置大小警告；桌面驗證不代表低階手機載入與反應速度已達標。

## 實機持續試用

同網路 iPhone 持續試用可使用後端的靜態網頁託管與 macOS LaunchAgent，操作見 [後端常駐服務說明](../backend/README.md#同網路-iphone-的-mac-常駐服務)。此方式使用已建置的網頁與同來源 API；程式修改後須重新建置、安裝常駐版本，並非即時熱更新。原生 WebView 另提供載入進度、連線錯誤／逾時／網頁程序中止提示及重試，需安裝新版 App 才生效。

### clean-ver 分支整合（2026-11-08）

流程、對話、補助總覽及樣式以 `feat/chat-ui` 為準；整合排序／跳題、地域文件及正式 PDF 表單分支。身分沿用農保、榮民等獨立欄位，不新增互斥的單選身分。地方文件依戶籍、居住或受理地的原文依據分類，未確認及其他地區要求保留在另表，戶籍不能代替受理地。畫面、文字匯出及 PDF 使用同一份回答投影，個人填答仍需勾選才揭露。

資源詳情的「申請表與填寫」可按需載入空白 PDF，使用者逐項確認本人資料後在裝置內填入，並核對、下載或分享。替他人查詢只提供空白表單；簽名、勾選及已知錯位的共用姓名欄保留手寫。編輯、撤銷確認、關閉面板或切換資源／對象後，舊 PDF 不可繼續使用。PDF 需由後端 `/api/forms/{file}` 提供；部署應設定 `FORMS_DIR`，不能以只有前端建置成功作為交付驗收。

# Gemma 4 E2B 微調實驗

原始資料為 `backend/data/subsidies.json`，不修改。模型、checkpoint、套件與轉換暫存只存 GPUtw；本機 `artifacts/` 僅放小型資料與報告，不提交。正式 App 尚未接入本實驗模型。

## 第一階段：可重現的來源抽取試驗

```sh
python3 training/prepare.py
python3 -m unittest discover -s training -p 'test_*.py'
```

先按 related_ids、同名與相同 program URL 分組，再固定雜湊切分。只有原資料標記 verified 的紀錄進入本輪；標記不是重新查核政策有效性的證明。四個任務是福利內容、期限、辦理流程及對象原文抽取，答案保留原文與來源 ID。文件清單的條件可能不完整，因此本輪不以 required=true 生成無條件文件要求。

這是流程與格式試驗，不能宣稱已學會口語需求理解或完整福利問答。模板測試不代表自然語言能力；語意上相同、但沒有共用 ID／名稱／URL 的方案仍須人工確認分組。

## 需求理解與合併試驗

```sh
python3 training/prepare_needs.py
python3 training/combine.py
```

`prepare_needs.py` 對齊現有前端 `NeedInterpretation`：八種 situationIds、候選 age／region／is_student／household_type、uncertain、輸入原文 evidence。合成案例不含真實申請人資料，訓練語句變體不分散到評測集；驗證與測試另寫不同語句。包括居住地不推定戶籍、家人年齡不當本人條件、否定、改口及不明需求。這些標註仍未經獨立人工驗收；數量小，不能代表所有臺灣口語。

合併後 588 筆訓練、36 筆驗證、32 筆保留測試。試驗分任務抽取驗證題；解讀任務另外看標籤與欄位正確率，原文引用需在輸入中存在。候選欄位一律要經使用者確認，不能直接進資格判斷。正式手機整合尚未完成。

## 遠端執行

本輪原先使用 `/vault/townpass/20261107`，實測出現讀取 Errno 5 與 SFTP close failure，已中止該次下載並改用 GPU 主機的 `/workspace/townpass` 本機磁碟，沒有使用 Mac 儲存大型權重。停止執行個體會清除 `/workspace`，因此 adapter／最終模型必須先備份私有模型庫並核對 SHA-256；本次不信任 `/vault` 作唯一副本。不得上傳 SSH 私鑰或 GPUtw API 金鑰到 GPU 主機。Hugging Face 上傳憑證另行透過加密通道提供到暫存檔，不寫入程式碼、模型或日誌。

以相容 Blackwell 的 PyTorch 環境執行；安裝版本見 `requirements-gpu.txt`，實際試驗另存環境紀錄。5090／torch 2.11.0+cu128 的 BF16 矩陣運算與反向梯度已完成 smoke check。手機匯出使用獨立 venv，避免更動訓練依賴。不在 Mac 安裝或下載模型環境。

```sh
HF_HUB_DISABLE_XET=1 HF_HOME=/workspace/townpass/hf-cache python training/run_pilot.py \
  --data training/artifacts/combined --out runs/combined-http-003 \
  --steps 64 --eval-limit 15 --token-file /tmp/townpass-hf-token
```

原版與微調版使用相同驗證題、提示與生成條件。訓練程式僅讀 validation；`evaluate_checkpoint.py` 在候選固定後一次性評測 test，不用測試結果挑參數。輸出包含環境、模型 revision、資料雜湊、token 數、原版與微調回答、訓練時間、峰值顯存及未完成項目。不截斷監督答案，過長樣本明列排除；模板／token 邊界不一致即停止。

本次已解決兩項套件相容性問題：Gemma 音訊模組使用 eager、文字與影像使用 SDPA；Transformers 5.20.2 使用 `warmup_steps`。HF Xet 傳輸曾停滯，改用官方 `HF_HUB_DISABLE_XET=1` 完成下載。這些重試發生在實際訓練前。

第一輪完成後依證據決定是否擴大：建立經審閱的口語需求與未知／矛盾案例，對齊前端情境 ID 和欄位；固定獨立測試集；以資料來源事實、格式與錯誤推定作驗收；最後測合併、LiteRT 匯出、量化退化與實機離線運作。通過訓練不等於通過上述驗收。

`publish.py` 只允許上傳到既有私有模型庫，採明確檔案白名單，並核對遠端 adapter 的 SHA-256。`merge_adapter.py` 使用固定原始 revision 在雲端 CPU RAM 合併，不把 4-bit 訓練載入狀態當成可直接部署的完整模型。

## 手機格式匯出實測

雲端CPU RAM合併後，以獨立venv的 `litert-torch-nightly==0.11.0.dev20261107` 匯出，`litert-lm==0.19.1` 執行。參數為純文字、`dynamic_wi4b32_afp32`、2,048-token cache、prefill 128/512、external embedder，未匯出影像或音訊編碼器。

```sh
HF_HUB_DISABLE_XET=1 HF_HOME=/workspace/townpass/hf-cache litert-torch export_hf \
  --model=/workspace/townpass/merged/combined-http-003 \
  --output_dir=/workspace/townpass/export/combined-http-003 \
  --task=text_generation --externalize_embedder=True \
  --cache_length=2048 --prefill_lengths=128,512 \
  --llm_metadata_max_num_tokens_override=2048
```

實際產出 `model.litertlm` 為2,843,315,968 bytes（約2.84 GB／2.65 GiB）。`evaluate_mobile.py` 在雲端CPU執行相同15題，14/15符合schema及完整答案；原PyTorch候選為15/15。失敗題把 `uncertain` 輸出成布林值、`evidence` 輸出成字串。這是量化、執行引擎及模板差異的整體比較，不能單獨歸因於量化。雲端CPU跑完15題約46.9秒，不代表手機速度。

因此匯出檔仍是未驗收的實驗產物，不能作正式App模型；尚未在真實手機上確認下載、記憶體、速度、離線運作與錯誤回退。`publish_mobile.py` 僅上傳指定檔案到既有私有模型庫，並以固定提交的LFS SHA-256確認備份。

## 第二輪：改善需求理解並監測能力退步

使用者已授權繼續調整，並要求避免一般能力退步。第二輪從同一固定原版revision重新開始，不疊加第一輪adapter。凍結原模型，只在文字attention的q/v投影訓練LoRA r8／alpha16／dropout0.05；不修改embedding、輸出頭、MLP或音訊／影像模組。BF16載入與訓練，學習率3e-5、warmup8、gradient clip0.5、micro batch1、累積8，最多128步。相較第一輪縮小更新範圍並降低學習率，但這些措施本身不是不退步的證明。

`prepare_v2.py` 產出684筆：436需求理解、168一般任務replay、80完全虛構的來源引用練習。這輪不以真實政策金額／期限作監督答案。資料為合成及程式標註，已經AI代理檢查，未經真人審閱。40題development（24需求／16一般）不訓練；舊32題僅作已知回歸測試。

獨立AI代理另行建立56題保留集（32一般能力、24需求），未讀取第二輪訓練資料；資料SHA固定為 `2b45bda483c15ef9a448e9d986a84589e107c52911a21e3f705843b081795144`。另外以固定seed分層抽取[cais/mmlu](https://huggingface.co/datasets/cais/mmlu) 8科各8題，來源revision `c30699e8356da336a370243923dbaf21066bb9fe`，MIT授權。這64題採zero-shot成對比較，不代表官方完整MMLU分數，也無法排除原版預訓練時見過題目。所有保留集只在候選固定後使用，不據此調參。

選擇規則事先固定：只比較64／128步的development結果；原版答對的一般題不能變錯，原本符合單字母格式的題不能違反格式；需求內容不得減少符合數，且內容或嚴格格式至少一項改善；所有需求題需符合schema與候選欄位，uncertain需與標註字串集合完全相同。後者是保守的精確比對，可能拒絕語意合理的改寫，不假裝為語意判斷。符合規則者選需求題符合數最高者，同分優先較早checkpoint；全不通過則不採用，不放寬門檻。凍結候選後才執行新保留集、MMLU子集及舊回歸題；原本正確的來源引用也不得退步。

`v2_metrics.py` 將JSON格式、情境／欄位、uncertain存在性與精確比對分開。evidence是輸入子字串只證明來源存在，不證明語意支持；最終還需獨立逐題檢查推論。即使小型測試通過，也不能宣稱模型所有能力都沒有退步。未通過候選僅私有備份，不合併為正式App模型。若development全不通過，固定用最後128步候選作後續診斷，不據新測試改選或撤銷未採用結論。若值得匯出，還要另測量化與裝置端執行；不能把BF16結果直接當成手機結果。

## 第三輪：自然口語教材與原版行為保留

2026-11-07 使用者授權第三輪：保持手機端執行、提升需求理解與專業性，允許依測試調整。調整僅使用 development；最終 holdout 在候選固定後才開封，開封後不得再把同一組視為未見測試。這輪是專用需求整理任務的試驗，不是通用模型能力的複製，也不對政策資格作自動決定。

教材由獨立 AI 工作編寫自然生活語句並附短標註理由，另一工作撰寫評測，主工作審查。所有資料明示 AI 合成／AI 審閱，不宣稱真人標註。正式採用仍需要人工抽查及實機驗收；研究訓練可在 AI 審查後進行。`prepare_v3.py` 只接受與教材 SHA-256 相符的逐筆准入名單，檢查結構、型別、原文證據及精確重複；語意相似與推論有效性仍另審。

原版 revision 不變，從原版開始 BF16 q/v LoRA，初始學習率 1e-5、r8/alpha16、128 步、每32步開發集評測。一般 replay 採 SFT + 0.2 × KL(P原版 || P微調)，只在 replay 的最多8個 completion 預測位置計算，分塊轉 FP32；同一模型暫停 adapter 取得原版分布，沒有第二份常駐基礎模型。這是被測方法，不能保證不遺忘。先做2步 GPU smoke 驗證反向傳播，再完整訓練。若有明確開發集問題，可另存一次有理由的修訂試驗，不循環查看最終題目調參。

格式、標籤、欄位、證據原文存在性與不確定資訊分開報告。uncertain 不再逐句精確相等；主題詞只作自動代理指標，須另外審查語意。不將格式改善等同智力提升。一般題的生成額度為128 tokens，需求為256 tokens，記錄截斷；配對比較必須使用相同提示、生成參數與題目。

本輪僅使用單張5090、既有餘額，初始一小時平台自動停止；不自動加值。檔案、模型下載與套件限雲端，本機只有小型程式／資料／報告。結束前將候選與報告備份原有私有模型庫並核對雜湊，再停止本輪個體。不動其他執行個體及其他工作中的前後端修改。

通過開發集及獨立驗收才考慮正式手機匯出；匯出須重新檢查量化／執行引擎的退化。雲端CPU成功不能稱手機實測完成。不通過時保留候選與診斷，原版保持可回復。

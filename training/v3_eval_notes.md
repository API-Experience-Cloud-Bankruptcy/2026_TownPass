# V3 獨立評測資料說明

本組是新寫的 AI 合成測試案例，不是真人提出的需求、不含真實申請人資料，也未經真人標註或審閱。作者僅讀專案 README、training/README.md、福利前後端實作契約及前端 NeedInterpretation 型別；未讀舊 prepare*.py、訓練資料或其案例。README 中的既有錯誤類型用來確認任務界線，不能因此聲稱與過往所有文字或模型預訓練完全獨立。

- development：v3_eval_dev.jsonl，32 題需求理解、32 題一般任務；可用於候選開發與調整。
- holdout：v3_eval_holdout.jsonl，32 題需求理解、32 題一般任務；只供候選、提示、生成設定及評分規則全部固定後的最終成對評測。不得用來生成訓練案例、選 checkpoint 或調整門檻。封存是使用流程約束，未設定檔案存取隔離。
- 兩組的具體情境族、人物安排與解題物件分開編寫；不是將同一底稿改名字或數字後拆組。檢查了 ID、category、去標點後完整 user 提示均不跨組重複。相同能力與語意挑戰仍會重複出現，因為兩組都測同一任務。此檢查不能證明與外部語料不存在語意重複。

## 檔案契約

每行為一個 JSON 物件，基本欄位為 id、task、category、prompt、expected、completion；有待確認內容的需求題另附 uncertainty_markers；非選擇一般題另附 answer_type=exact，需檢查格式者附 format_regex。task 為 interpret 或 general；prompt 依序為 system、user；completion 只有一則 assistant 訊息。兩組同任務共用本次獨立寫出的 system 提示。category 是具體情境族識別，不是額外的模型輸出標籤。

interpret 的 expected 是四欄物件：situationIds 字串陣列、candidateFields 物件、uncertain 字串陣列、evidence 字串陣列。completion 是同一 expected 的 JSON 文字。evidence 不是物件，所有片段逐字存在於 user 輸入。general 的 expected 及 completion 是相同的答案字串，依題意為單字母或指定短字串；有換行要求時保留實際換行。需比較格式與內容時，應分開呈現，不將單字母格式符合誤當答對。

## 需求標註界線

只標實際要求的協助：living 生活開銷、elder 長者照顧、study 就學、family 育兒與家庭照顧、health 醫療與身心健康、disability 身心障礙支持、housing 住屋、work 工作。身分或背景只是順帶提及時不增加需求標籤。明確否定或撤回的需求不保留；真正並列的需求則多標。照顧長輩採 elder，照顧孩子採 family；復健與輔具同時詢問時可並列 health、disability。

candidateFields 只允許 age、region、is_student、household_type。age 是明確單一申請人的整數歲數，未解析的衝突、概略歲數與協助者歲數不填。region 是戶籍縣市，採臺字標準名稱，不從住處、辦證地、工作地、學校或只有區名的地址猜測。is_student 只取明確當前就學陳述；問學費不自動推定在學。household_type 只取明確現行一般戶、低收入戶或中低收入戶陳述，不從缺錢、單親、否認低收或舊核定推定。已更正者取最後明確說法；未解決矛盾留空。多位對象不合併個人欄位。

uncertain 是簡短標註用語，不要求使用者說出這些字。僅對題目中實際顯示的未知、矛盾或對象不清列待確認，不羅列所有沒提到的欄位。不同合理的簡短改寫可能被精確字串比對判錯，因此應另報情境／欄位、uncertain 是否存在與語意審閱，不把 exact match 當完整理解。evidence 子字串檢查也只證明引用存在，不能證明推論正確；片段可有其他同樣合理的選取方式。

所有需求案例都不含政策金額、政策日期、法定資格答案或機關核准判斷。一般題中的日常數量與價格僅供算術，與福利規則無關。

## 一般任務與複核

每組皆有 6 題閱讀、6 題算術、6 題邏輯、4 題常識、4 題資料不足、6 題格式遵循。選擇題均為四選一，編寫後再依題意求解，核對只有一個正解。12 題算術另用運算式重算；開發集的文字字數另用程式重算。閱讀及邏輯以題內資料作推導；資料不足題不可猜測個人或即時事實。常識題只用穩定、簡單的日常情境。

資料作者另做同一 AI 的第二次語意檢查，釐清一個家庭需求案例的申請人文字後再固定檔案；這不是獨立真人複核。程式已檢查 128 行可解析、任務與筆數、唯一 ID、schema、候選型別、八類標籤覆蓋、evidence 逐字存在、completion 與 expected 一致、單字母題格式、跨組完整提示不重複及上述運算。執行檢查時不輸出 holdout 題目或答案。

## 解讀限制

這是小型、刻意涵蓋邊界的固定測試，不是隨機抽樣民眾需求、完整臺灣口語分布、官方通用能力基準或所有能力無退步的證明。作者與訓練資料作者分離能減少直接模板洩漏，不能排除共同模型偏差。不得因答對這些題就宣稱真人已驗收、福利資格正確、模型具有全面智慧，或可直接接入申請判斷。凍結後若發現標註問題，應記錄問題與版本，不能藉反覆修改 holdout 追求有利分數。

## 最終凍結：評分介面自洽檢查

未修改 v3_metrics.py，逐題將原有標準 completion 傳入 evaluate_answer。新增 uncertainty_markers 只描述待確認主題及替代表達詞組，不改需求標籤、候選欄位、標準文字或證據；每個有 uncertain 的案例皆明列詞組，避免評分器預設關鍵字漏接合理標註。詞組命中仍只是待審標記，不能證明完整語意。

一般任務的格式練習及明確要求數字格式的算術短答另附 format_regex；正確性仍由 expected 判斷，正則只檢查可操作的輸出結構。指定固定文字的格式題可能同時約束內容，不能將這部分誤稱獨立格式能力；其他未列正則的非選擇短答保留 format_not_assessed，避免用 exact 正確與否冒充格式評估。

最終各組 64/64 標準回答通過 correct 及 strict，自洽檢查不是模型成績。每組 32 題一般題有 27 題格式已評估、5 題格式未評估；6 題格式練習全部已評估。此後資料及標註凍結，holdout 僅供固定候選最終評測。
